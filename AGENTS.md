# Учебный проект

- Материалы курса и учебный конспект находятся вне репозитория: `/mnt/projects/me/obuchenie/ai-files/`. Перед планированием сверяйся с относящимися к задаче материалами; учебные заметки и личные переписки в Git не добавляй.
- Каждый следующий урок или шаг Алексей проходит в новом диалоге. В начале читай учебный конспект и уточняй у Алексея текущий урок/шаг и его статус; не начинай следующий автоматически. Важные решения, открытые вопросы и результат шага сохраняй по ходу работы в подходящих документах без отдельного согласования: рабочие сведения — в проекте, учебный контекст и статус — в конспекте вне Git. Завершение урока/шага отмечай со слов Алексея, отдельно от технической готовности.
- Перед каждым значимым шагом коротко и простыми словами объясняй Алексею, что делаем, зачем это нужно по курсу и как проверить результат. Новые термины поясняй на понятных примерах, не предполагая технических знаний. Цель — помочь разобраться в процессе, а не просто подтверждать действия агента; следуй этапам задания Хекслета.
- Сообщения коммитов — Conventional Commits с описанием на русском языке, без служебных подписей ассистента.
- Каждый коммит реализации должен ссылаться на соответствующий GitHub-тикет: указывать `Refs #<номер>` в теле сообщения.

## Каркас

- Запуск приложения — `mise run dev`.
- Тесты — `mise run test`.
- Линтеры и проверка форматирования — `mise run lint`.
- Полная проверка локально и в CI — `mise run check`.
- Установка, сборка и остальные команды описаны в [README.md](README.md).
- `backend/` — Go/Gin; `frontend/` — React/Mantine; `api/main.tsp` — источник API.
- Не редактировать вручную `api/generated/`, `frontend/src/api/` и `backend/internal/api/generated.go`: использовать `mise run generate`.
- Не менять служебный workflow Хекслета. Собственные проверки — `.github/workflows/check.yml`.
