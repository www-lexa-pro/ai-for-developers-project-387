# Обсуждение правил записи на звонок

Согласованные с Алексеем решения по заданию проекта. Обсуждение продолжается;
документ пока не является законченной спецификацией.

Ключевые согласованные решения оформлены отдельно:

- [Единый календарь и проверка пересечений](adr/0001-shared-booking-calendar.md)
- [Хранение данных в памяти одного экземпляра](adr/0002-in-memory-storage.md)

## Расписание и окно записи

Согласовано 13 ноября 2026 года:

- Часовой пояс календаря — Europe/Moscow. Время показывается гостю как московское.
- Рабочие дни — понедельник–пятница, с 09:00 до 18:00, без перерыва
  и исключений для праздников. Встреча полностью помещается в рабочие часы.
- Окно записи — 14 календарных дат начиная с завтрашнего дня по Москве.
  Выходные входят в окно, но недоступны для записи.
- Начала встреч предлагаются каждые 30 минут от начала рабочего дня,
  независимо от длительности типа встречи. Например, встреча на 45 минут
  с 09:00 исключает старт в 09:30, но допускает 10:00.

## Типы встреч и данные гостя

Согласовано 13 ноября 2026 года:

- Владелец создаёт тип встречи на отдельной странице без авторизации.
  Страница доступна любому, кто знает адрес. Новый тип сразу виден гостям.
- Название обязательно: 1–100 символов, значение из одних пробелов
  не принимается. Описание необязательно: до 1000 символов.
- Длительность — целое число минут от 1 до 540, не обязательно кратное 30.
- В первой версии есть только создание типов, без редактирования и удаления.
- Гость указывает обязательные имя (1–100 символов) и email
  (до 254 символов с проверкой формата). Телефон и комментарий не собираются.
  Приложение не отправляет письма; email нужен владельцу для связи.

## Бронирование и список владельца

Согласовано 13 ноября 2026 года:

- Кнопка «Записаться» сразу создаёт бронирование. До отправки формы время
  не удерживается. Отмены и переноса в первой версии нет.
- После успеха гость видит название встречи, дату, начало и окончание
  по Москве, своё имя и email.
- При одновременных запросах на пересекающиеся интервалы успешно
  выполняется только один. Остальные получают сообщение «Это время уже
  занято»; имя и email остаются в форме, доступные слоты обновляются.
  Так же обрабатывается время, занятое во время заполнения формы.
- На отдельной странице без входа владелец видит все ещё не начавшиеся
  встречи всех типов, ближайшие первыми, без ограничения окном 14 дней.
  Для каждой показаны тип, дата, начало и окончание по Москве, имя и email.
  Уже начавшаяся встреча не входит в список предстоящих.
- Страница владельца и данные гостей доступны любому, кто откроет её адрес:
  авторизации в учебном проекте нет.

## Хранение

Согласовано 13 ноября 2026 года: типы встреч и бронирования хранятся в памяти
одного работающего экземпляра приложения. При перезапуске они сбрасываются;
это ограничение должно быть явно указано в README при реализации.

## Начальное состояние и пограничные ситуации

Согласовано 13 ноября 2026 года:

- При каждом запуске автоматически добавляются три типа встреч с короткими
  описаниями по смыслу: «Знакомство» (15 минут), «Консультация» (30 минут),
  «Подробный разбор» (60 минут). Они доступны для обычной записи;
  владелец может создавать дополнительные типы. Бронирования при запуске
  отсутствуют.
- Календарь показывает все 14 дат. Выходные и полностью занятые дни
  недоступны для выбора. Если во всём окне нет свободного времени,
  показывается сообщение; окно не расширяется автоматически.
- При отправке сервер заново проверяет московскую дату, окно записи,
  рабочие часы, шаг начала и пересечения. Если день выпал из окна,
  бронирование не создаётся: имя и email сохраняются в форме,
  календарь обновляется, гостю предлагается выбрать новое время.
- Во время отправки кнопка записи недоступна, после успеха форма
  заменяется подтверждением. При обрыве связи с неизвестным результатом
  показывается сообщение о неопределённом результате и предложение
  обновить свободное время. Автоматических повторных отправок и отдельного
  механизма распознавания повторов в первой версии нет.

## Навигация и повторные записи

Согласовано 13 ноября 2026 года:

- Главная страница — каталог типов встреч для гостя. Выбор типа открывает
  календарь и форму записи. После подтверждения можно вернуться к каталогу.
- Ссылка «Для владельца» на главной открывает страницу списка предстоящих
  встреч и создания типов встреч.
- Один гость может бронировать несколько непересекающихся встреч.
  Типы с одинаковыми названиями разрешены. Типы и бронирования различаются
  по внутренним идентификаторам, а не по названиям, именам или email.
- Email не подтверждается.

## Обязательные требования задания

- Владелец календаря один и задан заранее; регистрации, авторизации,
  внешних календарей и уведомлений нет.
- Пересечения запрещены между всеми типами встреч, включая частичные
  наложения и одновременные запросы. Начало следующей встречи может
  совпадать с окончанием предыдущей.
- Контракт API проходит цепочку TypeSpec → OpenAPI → клиентский SDK.
  Существующий стек и генерация каркаса сохраняются.
- Итоговое приложение собирается в Docker-образ и запускается в контейнере;
  конечная цель задания — запуск сервиса в облаке.
