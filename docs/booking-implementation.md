## Каталог и прямые ссылки — #6

16 ноября 2026 года реализован каталог из API и страница выбранного типа.
Типы хранятся в памяти экземпляра сервера; новый экземпляр создаёт три начальных
типа с новыми случайными идентификаторами. Список сохраняет порядок создания.
Старый или неизвестный идентификатор возвращает 404 с постоянным кодом
`meeting_type_not_found` и сообщением «Этот тип встречи больше недоступен».

Контрактная цепочка:

1. `api/main.tsp`: `MeetingType`, `listMeetingTypes`, `getMeetingType`.
2. `mise run generate` создаёт `api/generated/openapi.yaml`,
   `frontend/src/api/` и `backend/internal/api/generated.go`.
3. `backend/main.go`: HTTP-обработчики сгенерированного интерфейса,
   начальные типы и сохранённый health.
4. `frontend/src/App.tsx`: вызовы сгенерированного SDK; каталог и прямой адрес
   `/meeting-types/{id}`; ожидание, ошибка с ручным повтором, пустой список,
   недоступный тип и возврат. Запоздавшее чтение не подменяет актуальный экран.

Проверки включены в `mise run check`:

- `backend/catalog_test.go`: HTTP-каталог, порядок и данные, чтение,
  новые идентификаторы у нового экземпляра и недействительность старых ссылок.
- `backend/main_test.go`: сохранённый дымовой тест сборки и запуска отдельного
  процесса с чтением health.
- `frontend/tests/catalog.test.tsx`: действия пользователя и видимые состояния;
  управляемые ответы только на сетевой границе, SDK остаётся настоящим.

Наблюдавшиеся red → green:

- Чтение: HTTP 404 для существующего идентификатора вместо 200 → операция

## Доступность и выбор времени — #8

16 ноября 2026 года добавлена операция `GET /api/meeting-types/{id}/availability`.
Ответ включает московский часовой пояс, первую и последнюю даты окна и все
14 дат единого снимка. Сервер сообщает причины недоступности `weekend` и
`fully_booked`; слоты содержат точное начало и окончание с часовым смещением.

`backend/schedule.go` получает текущее время, длительность и занятые интервалы
явно. В нём нет собственного чтения часов или хранилища. HTTP-обработчик получает
время и рассчитывает весь снимок под общей блокировкой календаря. Эта же
блокировка защищает чтение типов и предназначена для записи в следующей #9.
Начала идут каждые 30 минут; пересечения учитывают все занятые интервалы,
касание границ разрешено. Неизвестный тип возвращает прежний код 404.

`AvailabilityPicker` использует сгенерированный SDK и отдаёт выбранный слот
родителю через `onSelectionChange`. Дата и время выбираются вручную. Даты без
слотов заблокированы; смена даты использует загруженный снимок. Смена типа
немедленно скрывает прежние слоты и игнорирует запоздалые ответы. Обновление
сбрасывает время и сохраняет только всё ещё доступную дату. Есть загрузка,
ошибка с ручным повтором и пустое окно; отправка бронирования относится к #9.
`BookingPage` подключён к прямой странице выбранного типа.

## Создание типа владельцем — #7

16 ноября 2026 года добавлена страница `/owner`, доступная по ссылке
«Для владельца». Список типов и форма работают независимо: ошибка чтения
не запрещает создание. После 201 форма очищается, показано подтверждение,
созданный тип добавляется в конец списка; медленное чтение не теряет
результат создания. Тип сразу доступен через каталог и прямой адрес #6.

Контракт: `CreateMeetingTypeInput` → `POST /api/meeting-types` → SDK
`createMeetingType` → `backend/meeting_types.go` → `OwnerPage.tsx`.
Успех — 201 с созданным объектом. Некорректный JSON, включая `null` и
посторонние данные после объекта, — 400 с кодом `invalid_request`.
Ошибки полей — 422, код `validation_error`, сообщения в `fields`.
Все поля проверяются одновременно. Дробное число минут разбирается как
число и получает 422; неверный JSON-тип поля получает 400.

Нормализация обрезает Unicode-пробелы только по краям, сохраняет внутренние
переносы описания. Длины считаются по кодовым точкам Unicode в Go и JS.
Клиент использует Unicode White_Space, совпадающий с Go strings.TrimSpace.
Повторяющиеся названия разрешены; различение — по новым случайным id.
Чтение и добавление используют один mutex сервера; список возвращается копией.
`backend/validation.go` содержит общую нормализацию для последующих форм.

Форма блокируется до ответа. Потеря связи, 500 и непонятный ответ показывают
«Тип мог быть создан», сохраняя ввод. «Проверить список типов» выполняет
только GET; предупреждение сохраняется после проверки. Новое создание
возможно лишь по отдельному нажатию владельца. Автоматических POST-повторов нет.
Совпадение названия в списке не считается доказательством успеха.

Наблюдавшиеся red → green на согласованных границах:

- HTTP: создание возвращало 404 вместо 201 → операция TypeSpec,
  генерация и добавление в существующее хранилище.
- UI: отсутствовало поле «Название» → страница владельца и форма через SDK.
- HTTP: JSON `null` возвращал 422 вместо 400 → проверка JSON-объекта до
  сгенерированного декодера; также отвергаются лишние данные после объекта.
- UI: U+0085 не обрезался стандартным JS trim, в отличие от сервера →
  общая семантика Unicode-пробелов.
- UI: неполная ошибка 422 приводила к падению формы → проверка ответа
  и предупреждение о неизвестном результате.

Проверки: `backend/meeting_types_test.go` — создание и чтение, нормализация,
порядок и одинаковые названия, 201/400/422, все ошибки вместе, Unicode
100/101 и описание 1000/1001, минуты 1/540, 0/541 и дробь.
`frontend/tests/owner-types.test.tsx` — навигация, независимая форма,
пустой список, ручной повтор чтения, ошибки полей, границы Unicode,
блокировка отправки, неизвестный результат и проверка списка без POST.
Новые файлы интерфейса включены в lint; все тесты входят в `mise run check`.

Итог #7: полный `mise run check` прошёл 16 ноября 2026 года: линтеры,
проверка типов, Go HTTP/дымовой тест, 18 тестов интерфейса, сборки Go/Vite
и актуальность генерации. Это локальная проверка; GitHub Actions и
публикация работающего сервиса в рамках #7 не выполнялись.

## Бронирование гостем — #9

16 ноября 2026 года добавлен `POST /api/bookings` через исходный TypeSpec,
сгенерированные серверные типы и настоящий клиентский SDK. Подтверждение
содержит id записи, id и название типа, длительность, начало/окончание,
имя и email; окончание вычисляет сервер. Записи хранятся в том же календаре
под общей блокировкой; дополнительного хранилища и mutex нет.

Имя/email и предупреждение о неизвестной записи находятся в `App` выше страницы
выбранного типа: возврат к каталогу и смена типа сохраняют текущий процесс.
Успех очищает ввод сразу, сохраняя отдельное подтверждение, поэтому и переход
по истории открывает новую пустую форму. Данные браузером не сохраняются.

Во время отправки отключены поля, даты/слоты, обновление и переходы приложения.
409 сбрасывает время и обновляет календарь, 404 оставляет объяснение и ручной
возврат. Неизвестный результат (потеря ответа, 500, неполное либо несогласованное
подтверждение) сохраняет предупреждение, запрещает выбор до успешного чтения
доступности и требует нового выбора. Автоматического повторного POST нет.
Предупреждение сохраняется после обновления и при смене типа.
